## 本阶段方案（待人工审阅）

- JWT 使用固定 HS256、独立外部随机秘密、issuer/audience/到期校验；短期 access token 无 refresh。每次认证重新读取用户启用状态、auth_version 和当前数据库权限，使停用/改密/撤权立即生效。密码 BCrypt(12)，响应和日志不含凭据或哈希。
- 保留七类角色，不扩增五个 seed 用户。SYSTEM_ADMIN 管理全局 D；ROOM_ADMIN 只管理显式授权房间/座位和对应签到码，默认无房间授权。角色权限目录保留原文九项并加入必要 D 查询/设置/角色/签到码管理权限；未实现的业务权限只有字典，不开放业务端点。
- 空间新增/修改及启用状态可管理，暂不提供硬删除。修改房间归属/类型及座位归属仅系统管理员；后续已有预约的主数据变更须在 Phase 4/8 定义协调，不提前宣称已保证。
- 最大连续预约时长默认 4，存为正整数。D 提供读取/修改；具体预约时段及参数生效由 Phase 4 实现，当前没有 M1 调用。
- 签到码以可注入 Clock 和显式 ZoneId 计算日期，本地 Asia/Shanghai；8 位安全随机字符，(room_id,date) 唯一，重复/并发请求取同一条，不提供当日轮换。只允许系统管理员或已授权房间管理员读取，学生不能取码。内部 M1 凭据只用于校验 room/date/code，不完成预约签到；码不要求全局唯一。
- 业务成功 envelope 为 data/requestId，失败为 code/message/requestId。使用带 body 的 200/201，不在本阶段提供需要 204 的硬删除。404/409/422/401/403 等按真实语义返回；分页有上限。
- D 修改与审计同一事务，审计只保留身份 ID、动作、目标 ID、请求 ID、时间等必要字段；无请求体或签到码。应用身份不可更新/删除审计表。保留期限仍未定，不自动清理。
- 内部 HTTP 使用独立调用方凭据与明确路由能力，用户 JWT 不能替代；Nginx 不公开 internal。通知只记录后续契约，不把未投递消息冒充成功。

OQ-04/10/12/14 的本阶段选择在 API 和测试中具体化，作为 PR 待审草案；后续业务窗口、组织范围、审计保留和生产凭据流程仍保留。原文要求人工 review，不要求写代码前进行额外批准；本轮不自动合并 PR。
