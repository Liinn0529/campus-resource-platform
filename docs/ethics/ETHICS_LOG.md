## Phase 1 实际处理（2026-10-21–22）

运行状态页只展示服务名、版本、完整 Git SHA、构建时间和健康状态。连接失败时显示真实错误，不生成成功数据。Nginx 访问日志仅包含地址、方法、无查询参数的路径、状态与耗时；不记录请求体或查询字符串。四服务禁用默认用户自动配置，避免生成可用的默认登录密码。

本地数据库随机密码生成在权限 600 的私有 .env，Git 和 Docker 构建上下文均排除环境文件。临时下载、代理、依赖缓存与运行日志没有上传 GitHub。当前没有个人业务数据，后续引入身份、签到码与预约信息时仍需继续抽查日志和最小化字段；不将当前空业务阶段的抽查视为持续风险已消除。

## Phase 2 实际处理（2026-10-22）

仅显式 local profile 初始化五个虚构用户，使用私有环境变量生成 BCrypt 12 哈希；不将可用演示密码写入源码、迁移或日志。七个角色是角色字典，用户仍严格保持五人，不增加部门审批人或物业主管账号，也不私自给现有用户追加这两类角色。重复 seed 不更新既有用户密码或资源字段；非 local 启动不执行 seed，也不要求演示密码。

四服务各有独立 app/migrator 数据库身份，跨 schema 读写被 PostgreSQL 拒绝；应用身份不能执行 DDL 或修改 Flyway 历史。服务进程仍持有自己的迁移凭据，不能把账号隔离描述为进程无法访问迁移凭据。未来身份授权、审计、数据范围与生产秘密管理继续留待相应阶段审阅。

## Phase 3 当前方案（2026-10-24，代码与本地运行验收通过，方案待审）

身份使用短期 HS256 JWT，issuer/audience/到期与 authVersion 都由后端验证；每个请求重新读取当前启用状态、角色和权限，使后续请求不能沿用已撤销权限。改密/重置与状态变化使旧 JWT 失效，密码使用 BCrypt(12)。响应不含密码哈希或 authVersion，密码 DTO 的字符串表示隐藏输入；不生成默认生产用户或秘密。当前完整后端 49 项真实测试和前端 6 项及构建检查已通过，验证包括旧 JWT 失效、即时撤权、学生/跨房间拒绝与最后管理员保护；Compose 原库升级、七容器健康、实际登录/管理/范围/码/审计边界及 D 日志抽查也已通过；最终干净提交重建仍由交付流程记录，不把本轮验证视为风险永久消除。

房间管理员默认没有房间 scope，只能操作系统管理员显式授予的房间及座位；全局用户/角色、楼宇/房间创建、参数和审计查询同时要求 SYSTEM_ADMIN 与对应权限。七角色、14 权限及初始 35 条角色权限关系是全环境参考目录，local 用户仍严格为原五人；没有增加部门审批人或物业主管演示用户。管理员通过授权 API 创建的业务账号应有真实用途，不能把自动填充 seed 冒充真实运营数据。完整组织/部门范围与审批责任仍须后续决策。

每日签到码的草案只绑定房间和业务日期，由 Clock/显式时区决定今日，local Asia/Shanghai；8 位安全随机字符、同日不轮换、不承诺全局唯一。学生不能批量取码；M1 使用独立服务身份校验且只得到布尔结果，实际预约和签到资格仍由 M1 决定。当前没有 GPS、人脸、定位、蓝牙或设备个人信息采集。QR 载荷与签到窗口未定，不提前生成可绕过预约校验的成功流程。

D 修改与审计同事务。审计仅存 actor ID、来源、动作、目标 ID、requestId、时间；应用身份不能更新/删除记录。请求日志使用路由模板而非用户输入路径、查询字符串或正文，记录请求 ID、用户 ID、方法、状态和耗时；异常日志只留类型与关联 ID，不打印 SQL 参数或凭据。本轮实际 D 请求日志已抽查，未发现本地私有凭据或生成签到码；全服务未来业务和生产部署仍须持续检查。保存期限/导出/删除政策仍未定，不将缺少清理任务当作永久保存政策。

三个内部调用方使用独立 opaque 凭据，与用户 JWT 分离；只有 M1 可以验码，网关不公开 internal。秘密均来自私有环境，服务进程仍持有自身所需秘密，不能把网络/账号隔离说成凭据不可能泄露。生产轮换、初始管理员运维、HTTPS 和审计生命周期仍留对应阶段；当前没有通知投递实现，不对外声称消息已送达。

## Phase 4 当前方案（2026-10-25，代码测试通过，运行验收另记）

M1 每次经真实 D HTTP 获取当前身份和权限，不持有 D 的 JWT 签名秘密、不直接读取 D 表。预约 userId 只来自认证身份，未知 JSON 字段被拒绝；本人详情、取消和再预约对其他学生或系统管理员均返回相同 404，不泄露他人记录存在性，也不隐式授予代办权。当前 75 项后端测试通过，包括真实 D 即时撤权/停用与个人范围验证；生产组织角色及管理需求仍应独立审阅。

时间/取消政策源文档未穷尽，本轮形成明确草案：显式业务时区的整点，半开区间，当前参数最大时长，开始前本人 CREATED 可取消，重复取消幂等；历史再预约创建新记录并重新校验。不加入未要求的未来预约天数或一人多座限制。两类启用房间均纳入目录；M2/M3 后续仍必须经 M1 占用影响可用性。签到/自动完成/违约没有提前实施，不因时间流逝写惩罚状态。

取消保留原预约、来源占用与实际事件，释放只针对精确来源。历史与事件保存期限尚未决定，当前保留不代表永久保存政策。Compose smoke 结束时取消自己本次创建的预约，不删除历史，不扩充演示用户和空间；执行结果以 Phase 4 验收证据为准。M2/M3 来源只在隔离 PostgreSQL 测试夹具中验证，不向开发库填充虚构审批/维修。

D 主数据读取只是快照；不声称 D 停用/移动与 M1 提交跨服务原子。已有预约遇资源变更、维修优先级和受影响用户通知仍是明确未决项，不静默取消预约、不引入默认补偿。日志只记录模板路径、关联 ID、用户 ID、状态与耗时，异常只记录类型；实际 Compose 日志抽查和秘密扫描由本轮交付记录，不由文档先宣称通过。

## Phase9 成员二 Web 本地验收（2026-10-27）

真实浏览器验证发现：登录 API 返回成功且令牌写入当前会话后，学生首页仍被路由守卫拒绝。原因是 Pinia 的认证 getter 同时读取非响应式令牌存储，令牌变化不能可靠触发 getter 更新。认证改由后端校验后写入的响应式当前用户状态驱动；退出与401过期事件仍同时清除用户状态及令牌。Playwright 使用本地私有演示凭据，不记录密码、令牌或签到码。

端到端预约验证会真实创建预约。测试在结束时调用本人取消接口释放预约占用；按业务保留规则，取消历史不会物理删除，因此本地演示学生的历史列表会留下测试记录。真实写操作需显式设置 `RUN_REAL_E2E=1`，普通 Playwright 运行只执行只读角色/路由检查。本次请求发往本机前端及其本机 API 代理，未清空数据库卷或手工删除历史；运行前必须确认本机 API 代理指向本人开发环境，不得对共享或生产数据库执行写入验收。
